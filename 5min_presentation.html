2. 分析パイプラインの特徴

survey_analysis_pipeline/main.py がエントリーポイント

  1. Multi-LLM Orchestration: 複数LLMでの合意形成
    → これがエグゼクティブサマリーとなる
  2. 論点ベース分析: 法制審議会の論点に沿った意見集約
  3. クラスタリング: HDBSCAN + Embedding で類似意見をグループ化
  4. 立場検出: 賛成/反対/中立を自動判定
  5. マイノリティ検出: 少数派だが重要な意見を抽出

3. 論点ベース分析 (Ronten)

📋 *_ronten.txt による論点定義

  • 法制審議会の論点をあらかじめ {survey_slug}_ronten.txt として定義
  • ronten_loader.py: 論点ファイルを読み込み
  • ronten_matcher.py: 意見を各論点にマッチング

船荷証券の論点例

  • 機能的同等性（MLETR準拠）
  • 「支配」概念の具体化
  • 情報システム提供者の法的地位
  • 強制執行の実効性確保
  • 紙と電子の相互転換

→ 審議会で議論された論点と市民の意見を対応付けて分析

4. Multi-LLM 合意形成

orchestration/multi_llm.py

  • 複数LLM並列分析: Claude Opus, Sonnet, GPT, Gemini など
  • 相互評価: 0-10点で品質スコアリング
  • 反復ディスカッション: 合意閾値(80%)に達するまで議論
  • 差異の明確化: 合意点・対立点を抽出

出力成果物:

  • consensus_report.md - 統合レポート
  • discussion_log.md - 議論ログ
  • evaluation_matrix.json - 評価マトリクス

5. ペルソナアセンブリ

多視点分析のためのAIペルソナ定義

👔 政策立案者: 実装可能性、予算、ロードマップ
👥 一般市民: 生活への影響、公平性、わかりやすさ
🔬 批判的研究者: リスク、見落とし、長期影響
🗣️ 少数派代弁者: 多様性、包摂性、特定グループへの影響

Viewer機能: SSEリアルタイム配信 / ユーザーが議論に割り込み可能

6. 中間報告へのフィードバック対応

📌 指摘事項
  • レポート量が多すぎる (75ページ)
  • ノイズ・雑談が混入
  • 細かいスコアが読みにくい
  • 政策的価値での絞り込み不足
✅ 対応策
  • クラスタ単位でのフィルタリング強化
  • 関連性フィルター導入
  • エグゼクティブサマリー先頭配置
  • 詳細スコアは付録へ移動

🎯 高評価ポイントの維持

  • Multi-LLM合意形成: 独自性・技術的アプローチとして高評価
  • 制約条件の明示: レポート冒頭の前提条件記載は良い
  • Web UI統合: インタラクティブな分析システムへの興味

7. レポート: 船荷証券電子化法案

🎯 インサイトの質

  • 実務経験者の指摘: B/L単体ではなく関連書類（原産地証明書等）の一括電子化の必要性
  • 当事者視点: 中小企業の導入コスト負担、セキュリティ・システム障害への懸念
  • 専門知識: 電子記録における「支配」概念・権利移転時点の法的明確化の課題
エグゼクティブサマリー: 成功要因として①セキュリティ対策の徹底、②国際標準（UNCITRAL MLETR）への適合、③中小企業への導入支援、④段階的移行期間の設定が抽出された。

8. レポート: 国会議員定数削減法案

🎯 インサイトの質

  • 制度への深い理解: 「ゾンビ議員」（比例復活当選）制度への不満が賛否を超えて共有
  • 政治的影響の分析: 比例削減による新興政党・少数政党の国政参入困難化への懸念
  • 実務的視点: 削減目的・根拠が不明確、コスト削減効果も限定的という指摘
エグゼクティブサマリー: 単純な定数削減ではなく選挙制度全体の見直しとセットで議論すべき。制度の詳細理解が不十分な回答者が多く、丁寧な説明と国民への周知が必要。

9. レポート: 人工知能基本計画法案

🎯 インサイトの質

  • 専門的論点: AIの透明性・説明可能性、国産LLM開発による「AI主権」確保
  • 当事者視点: クリエイターの著作権保護、雇用への影響とセーフティネット
  • 制度設計への提言: ソフトロー中心への懸念、第三者機関による独立監査体制の必要性
エグゼクティブサマリー: 回答者の過半数が計画を「知らない」状態で認知度が低い。最終判断は人間が行うべき点、医療・防災・行政分野でのAI活用優先、AIリテラシー教育の必要性で広く合意形成。

10. 審査基準への対応

📊 インサイトの質: 専門知識・実務経験・当事者経験に基づく意見を
クラスタリング + マイノリティ検出 + 論点マッチングで抽出
📖 読みやすさ・伝わりやすさ: Multi-LLM合意形成による
エグゼクティブサマリー、クラスタ別の構造化された分析
✅ 正確性: 複数LLMの相互評価・クロスチェック、
元データへのリンク（セッションID参照）
💰 生成コスト: クラスタ単位でのLLM呼び出し最適化、
トークン使用量のトラッキング・レポート出力
